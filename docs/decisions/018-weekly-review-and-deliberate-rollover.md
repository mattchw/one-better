# ADR 018 — Finished-week facts and deliberate rollover intent

Status: implemented for the authorized Phase 7A slice, 3 October 2026. Supersedes earlier automatic destination-plan/predecessor-column proposals. No later feature is authorized.

One owned WeeklyReview belongs to one committed Plan whose Monday week has fully ended in the current User IANA timezone. Persist an explicit-save Draft note and logical-commitment decisions; finalize only once. Each decision references owned Review, Plan, logical commitment registry and Action, with kind, optional Carry budget and inspected source guards. Frozen context derives from existing immutable history; there is no new planning or execution snapshot. Finalized UPDATE/child INSERT or UPDATE are rejected by focused SQL triggers; there are no product DELETE/reopen/correction routes. Administrative fixture cleanup is outside product lifecycle.

Derive the union of original baseline and every ordered immutable Amendment by logical ID, retaining first appearance, first budget, latest budget before removal, dropped/final membership and frozen labels. Re-adding an Action keeps separate lineages. Original/final capacity, reserve and budget totals remain exact. Count planned TimeBlocks independently; cancelled context contributes no scheduled time. Actual elapsed milliseconds intersect exact current-User local Monday midnight through next Monday midnight. DST weeks may have 167/169 elapsed hours. All outcomes count without clipping to block intervals or inferring completion. Cross-week active contributions are fixed once the reviewed boundary ends, so they do not block finalization. Intersecting execution from older Plans is separately explained and counts toward the weekly actual total while retaining its original lineage.

Show seven local-date reflection states. Draft daily notes are indicated as unfinished only in a Draft weekly context; their text is not final evidence. Finalized weekly context includes only immutable DailyReflection text with finalizedAt <= WeeklyReview.finalizedAt. Later finalizations never appear as originally considered evidence. Do not copy seven bodies into Review storage.

Require Carry/Defer/Drop for every currently effectively mutable source, including commitments removed midweek. Carry starts with a blank explicit positive budget (1–10,080), Defer leaves ordinary Open work available, Drop archives its underlying Action at finalization and requires a clear separate confirmation. Multiple historical lineages of the same Action must choose a consistent kind; archive it once, and derive next-week duplicate prevention from Action membership. Different Carry budgets may express different prior slices; one Action may still enter the destination once.

Receipt → User NO KEY UPDATE → owned Review/Plan → sorted Goals → sorted current Milestones → sorted Actions. The owner lock serializes Review create/save/finalize and Focus/daily writes; existing source locks stabilize eligibility, relationships and every inspected source/parent version. All sources validate before any Drop. Reuse Action.archiveAction and the extracted existing replaceAction persistence inside the same receipt transaction. Freeze note/children, archive valid Drops, set finalizedAt/version and receipt atomically. Any source conflict or SQL failure rolls all effects back. Receipt replay precedes lifecycle/source checks, retaining original final decision DTOs after restart without repeated archival.

A finalized Carry is durable intent. The following week's Planning page shows frozen context, prior final budget and saved proposal; an explicit Add may choose a different budget. Create a Draft explicitly first. Use the existing weekly-plan.save path with an optional owned Carry proof checked inside its receipt transaction, then normal locked fresh source validation and ordinary new-week commitment IDs. Existing hashes remain unchanged when the optional proof is absent. No carry-application table, automatic Plan creation, commitment copying or Amendment. Already-present Action and committed destination states are derived and clearly explained. Review identity plus logical decision identity supply lineage without adding a predecessor column to existing immutable commitments.

Ownership comes solely from verified actor; receipts retain owner/UUID namespace, strict payloads, Origin and private no-store HTTP. Reads are coherent repeatable-read projections without receipts or provider calls. Unsaved browser choices survive ordinary conflict/retry in memory; saved Drafts persist in PostgreSQL. Conservative source changes require explicit review. No scores, AI, suggestions, automation, Calendar writes or new integrations. Complete a real full-week dogfood gate before selecting another feature. Real Google OAuth/list/FreeBusy/refresh/reconnect/disconnect remains a separate hard prerequisite for any future writes.
